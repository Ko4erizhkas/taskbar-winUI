# BarKit

Небольшая утилита для панели задач Windows 11:

- **Группировка** — запущенные приложения отделяются от закреплённых, но не запущенных: две группы с зазором и линией-разделителем между ними.
- **Прозрачность** — фон панели можно сделать полностью прозрачным, полупрозрачным цветным или акриловым. Работает при любом положении панели (снизу, сверху, слева, справа).
- **Поле «Сейчас играет»** — название, исполнитель, обложка и кнопки «назад / пауза / вперёд» прямо на панели задач. Положение настраивается: в начале, по центру, в конце перед треем или сразу после значков, плюс точный отступ в пикселях.

Окно настроек сделано на WinUI 3 (Windows App SDK 2.x), всё написано на C++/WinRT.

> Требуется Windows 11 с XAML-панелью задач (22H2 и новее). Проект рассчитан на 25H2 со штатной настройкой положения панели.

## Как получить сборку

1. Откройте вкладку **Actions** репозитория и выберите последний успешный запуск `build`.
2. Внизу страницы скачайте артефакт **BarKit-x64** и распакуйте его в постоянную папку (не во временную).
3. Запустите `BarKit.exe`. Устанавливать ничего не нужно: рантайм Windows App SDK лежит рядом с программой.

Значок BarKit появится в области уведомлений. Крестик в окне настроек только прячет окно; чтобы закрыть программу, выберите «Выход» в меню значка — панель задач при этом вернётся в исходное состояние.

**Обновление на новую сборку:** перезапускать Проводник не нужно. BarKit загружает в `explorer.exe` не `BarKitTap.dll` из своей папки, а её копию из `%LOCALAPPDATA%\BarKit\tap\<версия>`, поэтому файлы программы можно свободно заменять и пересобирать. Выгрузить DLL из `explorer.exe` нельзя, так что после выхода из BarKit копия остаётся в памяти Проводника, но ничего не делает; копия старой версии «засыпает», как только запускается новая. Старые копии с диска BarKit удаляет сам при следующем запуске после перезапуска Проводника.

## Как это устроено

```
BarKit.exe  (app/)                         explorer.exe
┌───────────────────────────┐              ┌──────────────────────────────────┐
│ окно настроек (WinUI 3)   │   реестр     │ BarKitTap.dll  (tap/)            │
│ значок в трее             │ ───────────▶ │  · следит за деревом панели      │
│ внедрение DLL             │  HKCU\       │  · меняет кисть фона             │
└───────────────────────────┘  Software\   │  · сдвигает значки по группам    │
        │                      BarKit      │  · добавляет медиа-поле          │
        └── InitializeXamlDiagnosticsEx ──▶└──────────────────────────────────┘
```

Панель задач Windows 11 — это XAML-интерфейс внутри `explorer.exe`, и публичного API для таких изменений у неё нет. Поэтому BarKit состоит из двух частей:

- **`app/` — BarKit.exe.** Окно настроек, значок в трее, автозапуск. Настройки пишутся в `HKCU\Software\BarKit`. При старте приложение загружает DLL в `explorer.exe` через `InitializeXamlDiagnosticsEx` — тот же механизм используют инструменты отладки XAML и TranslucentTB.
- **`tap/` — BarKitTap.dll.** Работает внутри `explorer.exe`: подписывается на изменения визуального дерева панели задач и следит за ключом реестра, применяя настройки на лету. Панель построена на системном XAML (`Windows.UI.Xaml`), а не на WinUI 3, поэтому DLL использует именно его.
- **`shared/Settings.h`** — общий для обеих частей формат настроек.

Что именно делает DLL:

| Функция | Как реализована |
| --- | --- |
| Прозрачность | Подменяет кисть у `Rectangle#BackgroundFill` (и `BackgroundStroke`) внутри `Taskbar.TaskbarFrame`; если Windows возвращает свою кисть — ставит нашу обратно. |
| Группировка | Определяет запущенные приложения по визуальному состоянию индикатора (`RunningIndicatorStates`) и визуально переставляет кнопки `Taskbar.TaskListButton` через `RenderTransform`. Разделитель — отдельный `Rectangle`, добавленный в сетку панели. |
| Медиа | Данные берёт из системного API `GlobalSystemMediaTransportControlsSessionManager`, элемент добавляет в корневую сетку панели задач. |

## Ограничения и что важно знать

- **Это вмешательство во внутренности Windows.** Имена элементов (`Taskbar.TaskListButton`, `BackgroundFill` и т. д.) нигде не документированы и могут измениться после обновления Windows. Тогда часть функций перестанет работать до правки кода — см. «Диагностика».
- **Группировка — визуальная.** Значки сдвигаются на экране, но внутренний порядок панели не меняется. При перетаскивании значков мышью они могут вести себя непривычно; запущенное закреплённое приложение «переезжает» в группу запущенных и возвращается обратно после закрытия.
- **Медиа-поле может перекрывать соседей** (кнопку виджетов, значки при заполненной панели) — подберите положение и отступ в настройках. На вертикальной панели показываются только обложка и кнопки, название — во всплывающей подсказке.
- **Режим «Акрил»** зависит от того, поддерживает ли окно панели системный фон; если нет — будет показан обычный полупрозрачный цвет.
- **Антивирусы** могут настороженно относиться к загрузке DLL в `explorer.exe`.
- **Защита от цикла сбоев:** если Проводник несколько раз подряд перезапустился после подключения BarKit, автоматическое подключение приостанавливается — в окне настроек появится сообщение и кнопка «Подключить заново».

## Диагностика

Всё лежит в `%LOCALAPPDATA%\BarKit` (кнопка «Открыть папку с логами» в настройках):

- `tap.log` — журнал DLL: подключение, найденные элементы панели, ошибки.
- `tree.txt` — дамп визуального дерева панели задач (кнопка «Сохранить дерево панели задач»). По нему видно, как элементы называются в вашей сборке Windows, — этого достаточно, чтобы поправить имена в `tap/XamlHelpers.h`.

## Сборка из исходников

Нужны Visual Studio 2022 или 2026 с рабочими нагрузками «Разработка классических приложений на C++» и «Разработка приложений WinUI», а также Windows SDK 10.0.22621 или новее.

```
msbuild BarKit.sln /restore /p:Configuration=Release /p:Platform=x64
```

При сборке из самой Visual Studio пакеты NuGet нужно один раз восстановить — VS не делает этого для C++-проектов с `PackageReference`. Выполните в «Developer PowerShell» из папки репозитория `msbuild BarKit.sln /t:Restore /p:Configuration=Release /p:Platform=x64` и переоткройте решение (без этого сборка падает с `MIDL2011: unresolved type ... Microsoft.UI.Xaml.Window`).

Результат — в `build\x64\Release\`.

При сборке из самой Visual Studio выберите платформу **x64**. Пакеты NuGet для C++-проектов студия сама не восстанавливает: первая сборка восстановит их и остановится с подсказкой, вторая пройдёт. Ошибка MIDL `unresolved type declaration: Microsoft.UI.Xaml.Window` означает именно невосстановленные пакеты. Тот же шаг выполняет GitHub Actions (`.github/workflows/build.yml`) при каждом push.

## Удаление

Выйдите из BarKit через меню значка, удалите папку с программой и, при желании, ключ реестра `HKCU\Software\BarKit` и папку `%LOCALAPPDATA%\BarKit`. Если был включён автозапуск — сначала выключите его в настройках.
